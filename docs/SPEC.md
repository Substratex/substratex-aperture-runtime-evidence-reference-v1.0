# SubstrateX Aperture™ Public Reference Specification

## 1. Purpose

Aperture reconstructs observable operational records into a governed runtime evidence object that can be measured, investigated, challenged, exported, and preserved without treating model explanations or UI labels as independent evidence authority.

## 2. Scientific object

The primary object is **Longitudinal Computational Behavior**: observable computational activity developing across ordered runtime.

Aperture does not claim access to hidden model thoughts, consciousness, intent, or private reasoning.

## 3. Ingestion contract

The ingestion boundary must distinguish:

- input representation,
- source family,
- applied adapter,
- selected Operational World.

Those concepts may be related but cannot silently substitute for one another.

A declared adapter may parse, segment, normalize supported structure, map roles/events, preserve source references, qualify uncertainty, expose missingness, and refuse unsupported input.

It may not fabricate events, invent participants, convert ambiguity into source fact, generate scientific telemetry, establish Basin Exit, compute formal lead time, or produce downstream conclusions.

Deterministic expectation:

```text
same source + same adapter version + same evidence-bearing canonicalization options
= same canonical runtime
```

## 4. Canonical runtime

The Canonical Runtime is the normalized computational representation created from qualified source evidence. It preserves, where available:

- ordered canonical units,
- roles and role transitions,
- event identity/family,
- source-span references,
- tool/operational records,
- time/coordinate references,
- missingness and ambiguity,
- transformation provenance.

## 5. Evidence computation

After canonicalization, Aperture may form the runtime event ledger, canonical spine, playback frames, telemetry, temporal markers, Worldline, CER, instrument findings, Human Read, authority state, Passport, and preservation artifacts.

## 6. Telemetry and legitimacy

Signals should identify their evidence/legitimacy posture. Public categories include:

- direct / source-observed,
- computed,
- derived,
- proxy,
- interpretive,
- experimental.

These are support/material classes, not a single scalar truth score.

## 7. Temporal markers

Marker semantics remain distinct:

- first weakening `t_aw`,
- candidate boundary `t_candidate`,
- confirmed Basin Exit `t*`,
- observable failure `tf`,
- recovery / re-entry.

A candidate does not become confirmed because a later failure exists. A precursor observed retrospectively is not automatically a prospective warning.

## 8. Lead-time rule

Formal lead time requires both a qualified exit and independently supported observable failure:

```text
Δt = tf - t*
```

Without `tf`, the run may expose an Open Watch / Post-Exit Watch interval but formal lead time is not computed.

## 9. Evidence governance

Evidence-Governed Computation™ requires every authoritative output to remain traceable to identified evidence under declared methods and within an executable claim boundary.

Evidence authority is not truth certification.

## 10. Runtime Evidence Authority

Runtime Evidence Authority evaluates whether the computed run satisfies the identity, provenance, legitimacy, sufficiency, disclosure, claim-lineage, and conformance requirements required for Passport issuance.

Passport issuance occurs after evidence formation; ingestion does not issue the Passport.

## 11. Runtime Evidence Passport

The Passport may bind or reference:

- source identity,
- canonical identity,
- run/record identity,
- source coverage,
- adapter/canonicalization versions,
- ingestion warnings and overrides,
- evidence sufficiency,
- claim boundary,
- export authority,
- evidence seal,
- explicit non-certifications,
- preservation status.

The Passport does not retroactively improve the source or erase limitations.

## 12. Operational World Mapping

Operational World Mapping adapts investigative context around a fixed evidence object. It may change language, guidance, case selection, instrument emphasis, and operator questions. It may not change canonical evidence computation or authoritative status.

## 13. Preservation

Evidence Artifact export is gated on a computed record with aligned run identity and Passport/evidence authority. Evidence Commons extends preservation across selected evidence objects and artifact types.

## 14. Claim boundary

Aperture may report observable/computed runtime structure and bounded findings. It does not independently establish hidden state, intent, consciousness, unique causation, objective truth, blame, safety, regulatory compliance, or universal prediction.
